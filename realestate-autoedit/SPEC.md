# 不動産ルームツアー動画 自動編集システム 仕様書

Claude Code で本番システム化するための仕様書。同じフォルダの `autoedit/` が、この仕様の実装。

---

## 1. ゴール

撮影者から届いた動画と物件資料を物件フォルダに置いて `python -m autoedit 物件動画/物件名` を実行するだけで、物件資料の読み取り(間取り図・物件情報・コピー案)から、カット選び・並べ替え・トランジション・テロップ入れまでを全自動で行い、TikTok 用の縦型ルームツアー動画(30〜70秒。内容が良ければ1分を超えてよい)を書き出す。

- 部屋をゆっくり見せる、高級感のある映像にする
- 移動中など不要な部分は使わず、見所だけを使う
- トランジションは派手にせず、上品で滑らかにする
- テロップのデザインと構成は、現状の TOALU 動画を踏襲する
- 最低限の形(カット済み素材にトランジションとテロップだけ入れる)でも動くように作る

## 2. 素材の受け渡しと入出力

### 2-1. 受け渡しの流れ

1. 撮影は外部の撮影者が行う。縦向き・60fps で、部屋ごとにクリップを分けて撮る(撮影ガイドは7章)
2. 撮影者から、動画と物件詳細資料(PDF や画像。間取り図入り)が LINE の「ファイル」送信で届く
   - 「写真・動画」で送ると画質が落ちるので、必ず「ファイル」で送ってもらう
3. 受け取った担当者が、次のフォルダ構成で保存する(LINE からの保存は手作業。自動化はフェーズ2)
4. `python -m autoedit 物件動画/物件名` を実行する

### 2-2. フォルダ構成(`config/project.yaml` で名前を変えられる)

```
物件動画/
  共通/                  全物件で共通の素材
    広告.png             TOALU ESTATE の広告画像(1080×1920)
    BGM/                 音源(複数あれば property.yaml の bgm で選ぶ。未指定は名前順で先頭)
    フォント/             実際に使っている書体ファイル
  阿波座○○/              1物件 = 1フォルダ
    素材/                撮影者から届いた動画(部屋ごとのクリップ)
    物件資料.pdf 等        物件詳細資料(PDF・画像)を直下にそのまま置く
    property.yaml        ← 自動生成(文言を直したいときはここを編集して再実行)
    floorplan.json       ← 自動生成(間取り図の読み取り結果)
    物件情報.json         ← 自動生成(資料から読み取った物件情報。確認用)
    出力/                ← 書き出し先
```

### 2-3. 入力

| 種別 | 置き場所 | 内容 | 必須 |
|---|---|---|---|
| 動画素材 | `物件名/素材/` | 縦向き・60fps・部屋ごとのクリップ(mp4 / mov) | ○ |
| 物件資料 | `物件名/` 直下 | PDF・画像(jpg/png/webp)。間取り図と物件概要(最寄駅・徒歩分数・間取り・特徴)が載ったもの | ○ |
| 広告画像 | `共通/広告.png` | 1080×1920 の静止画(TOALU ESTATE のカード) | 推奨 |
| BGM | `共通/BGM/` | 音源ファイル。動画より短ければループし、最後の1.5秒でフェードアウトする | 任意 |
| 書体 | `共通/フォント/` | 実際に使っている書体。無ければ Noto 系などで代用(6章) | 推奨 |
| `property.yaml` | `物件名/` | hook・キャッチ・CTA の文言。物件資料から自動生成する(4章⓪) | 自動 |

### 2-4. 出力(1回の実行で、動画・サムネ・投稿文がそろう)

| ファイル | 内容 |
|---|---|
| `出力/物件名.mp4` | 動画(1080×1920、30fps、H.264、BGM は AAC) |
| `出力/物件名_サムネ.jpg` | サムネイル(1149×1369、黒×ゴールドのテンプレート。10章) |
| `出力/物件名_投稿.txt` | 物件番号・動画冒頭テロップ・投稿タイトル・キャプションと、納品前チェックの結果(10章) |
| `出力/物件名_plan.json` | 構成表(どのカットを何秒使ったか、AI判定結果、使った広告・BGM) |
| `出力/物件名_カット確認.jpg` | カット確認シート(各カットの映像と付けた部屋名) |
| `完成/No.L036_物件名/` | 投稿するものだけ(動画・サムネ・キャプション)を物件ごとにまとめたフォルダ。動画は画質優先の納品版(HEVC。同じ画質でファイルが約半分。30MB未満に収まる範囲で一番高い画質) |

受け渡しはチャットで行う。確認用に動画を送り、「完成OK」が出たら完成フォルダの3点(動画・サムネ・キャプション)をまとめて送る。作業用マスター(`出力/物件名.mp4`)は H.264・CRF17。ドライブへの自動保存の仕組み(README)もあるが、今は使っていない。

## 3. 参考資料の分析結果

### 3-1. 目指す編集スタイル(参考動画 `videoplayback (1).mp4`、44秒)

- 0〜18秒は1カットの長回しで、ジンバルでゆっくり歩いて玄関→廊下→キッチン→リビング→庭まで見せている
- 18〜43秒はカット割りで、1カット2〜6秒(平均約3秒)
- 切り替えはほぼ普通のカットだが、前後のカットでカメラの動く方向と速さがそろっているので滑らかに見える
- 29秒付近に1回だけ、壁の縁が画面を横切って寝室に切り替わる「壁ワイプ」がある
- ラストはバスタブ横の小物にゆっくり寄り、0.7秒で黒へフェードアウト
- 高級感の大部分は撮影(一定速度・低速・暖色照明)から来ている

→ 編集側の役割は「安定区間だけを選ぶ」「動きの流れでつなぐ」「つなぎ目を上品なディゾルブでなじませる」「ゆっくり寄る」の4つとする。

### 3-2. 現状の動画(TOALU・阿波座の物件)の構成とテロップ

画面録画から採寸した(座標は 1080×1920 換算)。

| 時間の目安 | パート | 映像 | テロップ |
|---|---|---|---|
| 0〜1.9秒 | 見所 | 外観をあおりで | 「誰もが憧れる、この空間」極太明朝・白・斜体・黒のドロップシャドウ、y≈450 |
| 1.9〜6.8秒 | キャッチ | エントランス・共用部 3カット | 「阿波座駅3分の / デザイナーズマンション」2行、同書体、「阿波座駅」の上に傍点●、y≈380〜560 |
| 6.8〜8.7秒 | 広告 | 静止画(関西の高級賃貸なら TOALU ESTATE) | 画像内 |
| 8.7〜10.7秒 | ルームツアー開始 | 廊下 | 「ルームツアー START」字間広め・斜体・左へ流れながら消える、y≈960 |
| 10.7秒〜 | 部屋紹介 | 各部屋 | 英字セリフの部屋名(Living / bath room / toilet)+明朝のサブコピー、ふわっとフェードイン、y≈330 |
| 最後 | 映え + CTA | バルコニーからの眺め | 白枠+半透明黒ボックス「気になった方は詳細とコメント✓」y≈460 + 矢印 |

現状の切り替えは、普通のカットと、カメラを素早く振るパンが中心。新しいスタイルでは、この構成とテロップはそのままにして、映像の選び方とつなぎ方を上品にする。

### 3-3. CTA 矢印の修正(要件)

現状の矢印は水平で、先端が (878, 897) 付近にあり、アカウントアイコン(中心 ≒ (953, 960)、半径 ≒ 54px)の左上にズレている。

- 矢印は真横(左→右)でアカウントアイコンの中心を指す(当初は右下18°だったが、斜めは不自然なため変更)
- デザイン: 尾に向かって細く・透明になる軸 + 切れ込みのある矢じり。白に2重の影を付け、明るい背景でも見えるようにする
- 先端はアイコンの縁の14px手前で止める(アイコンに重ねない)
- 先端方向へ小さく「ツン」と押し出すアニメーションで目線を誘導する
- 位置は `config/style.yaml` の `telops.cta.arrow.target` で調整できるようにする
- アイコン位置は iPhone(1170×2532)の画面録画から採寸した値。機種で数十px変わる可能性があるので、`python -m autoedit.preview` でガイドを重ねて投稿前に確認する

## 4. 処理フロー

```
物件資料 ─▶ ⓪ 物件資料の読み取り(property.yaml・floorplan.json を作る)
素材 ─────▶ ① 安定区間の抽出 ─▶ ② 間取り図 ─▶ ③ AIによるカット判定 ─▶ ④ 構成の組み立て ─▶ ⑤ 書き出し
```

### ⓪ 物件資料の読み取り(`intake.py`)

- `物件名/` 直下の PDF・画像をまとめて Claude に渡し(PDF はそのまま document として)、1回の呼び出しで次を JSON で受け取る
  - 物件情報: 物件名、物件種別、最寄駅、路線、徒歩分数、間取り、専有面積、特徴(最大6個)。資料に無い項目は推測で埋めない
  - 間取り図: 載っていたファイル名、間取りタイプ、部屋一覧(表記、種類、帖数) → `floorplan.json`
  - hook の案3つ(全角14文字以内・1行)と、キャッチの案3つ(2行・各行 全角12文字以内・傍点を付ける語を《》で1か所)。作り方は下の「冒頭コピーのルール」
- 案の整え方
  - キャッチは2行にそろえ、《》が無い・壊れているときは最寄駅名を《》で囲む
  - 不動産の表示に関する公正競争規約で根拠なく使えない語(完全、完璧、絶対、日本一、最高、抜群、格安、超 など)を含む案は外す
  - 文字数に収まる案を優先し、1案目を `property.yaml` に採用、ほかの案はコメントで残す
- **冒頭コピーのルール**(0〜9秒で「この物件は何が特別か」を1つだけ伝え、続きを見たくさせる)
  - 構成: hook(0〜3秒)で感情・希少性を一言 → キャッチ(3〜9秒)で事実の裏付け(数字・立地・物件種別) → 映像はコピーを証明するカット(ガレージなら外観、眺望ならバルコニー)
  - 訴求ポイントの選び方(優先順): ①賃貸では珍しい希少性(ガレージ、大型犬OK、サウナ、専用庭、メゾネット、高層階、眺望) ②数字のインパクト(100㎡超、LDK20帖超、駅徒歩5分以内、30階以上) ③立地のブランド(梅田・北浜・心斎橋など) ④新築・デザイン
  - 使わない: 弱みになる数字(徒歩10分超、古い築年)、設備の羅列、どの物件にも言える言葉
  - hook は3つの型で1案ずつ作る: 憧れの暮らし型(「愛犬と、ガレージのある新築へ。」)/ 問いかけ・意外性型(「賃貸で、この広さ。」)/ 数字の断言型(「148㎡、新築の4LDK。」)
  - キャッチは1行目=一番の希少ワードや立地、2行目=物件種別+特徴。傍点(点滅)は一番の希少ワードに
  - サムネのタイトルも同じ訴求ポイントにそろえる
- `property.yaml` が既にあれば作り直さない(人が直した文言を消さないため)。作り直すときは `--regen-property`、または `python -m autoedit.intake 物件名 --force`
- APIが使えないときは雛形(「○○駅」入り)を作って止まり、担当者が文言を書いてから再実行する
- 読み取り結果は投稿前に担当者が目で確認する(徒歩分数・駅名は広告表示の根拠になるため)

### ① 安定区間の抽出(`analyze.py`)

- ffmpeg で 10Hz に間引いてフレームを取り(スマホの回転メタデータは自動で適用。日本語パスも可)、特徴点追跡(オプティカルフロー)からカメラの横・縦・前後の動きを推定する
- 次の区間は捨てる
  - 速すぎる(`max_speed` 0.7画面幅/秒超え): 部屋間の移動、振り回し、素早いパン
  - 手ブレ(滑らかな動きからのズレが `max_shake` 超え)
  - ピンボケ・ブレ(シャープネスがクリップ中央値の30%未満)
  - 暗すぎ・白飛び
  - 編集済み素材が混ざっていた場合のカット点(輝度ヒストグラムの急変)をまたぐ区間
- 残った区間は、両端を0.2秒ずつ削る(動き出しと止まりを避ける)
- スコアは「滑らかさ45% + 理想速度(0.25画面幅/秒)への近さ35% + シャープさ20%」。完全静止より「ゆっくり動いている」カットを高く評価する
- 4.6秒を超える長回しは、判定しやすいよう約3.6秒ずつに分割する(部屋ごとのクリップでも、1部屋を長く撮ったものは分割される)
- 横長素材や 60fps 未満の素材が混ざっていたら、解析ログで知らせる

### ② 間取り図(`floorplan.json`、または `vision.read_floorplan`)

- 通常は⓪で作った `floorplan.json` を使う。個別指定モードでは `--floorplan` に画像か JSON を渡す
- 使い道は2つ
  - 存在しない部屋の種類をAIが選ばないように、③の判定を制限する(選べる種類の一覧から外す)
    - LDK があればリビング・ダイニング・キッチンを許す。寝室と洋室は表記ゆれが大きいので、どちらかがあれば両方許す
    - 外観・エントランス・玄関・廊下・収納・眺望は間取り図に載らないことが多いので、常に許す
  - 部屋名テロップの表記を決める
- 現在地ハイライト表示(間取り図を小さく出して今の部屋を光らせる)は、画面が散らかると高級感が落ちるので初期版では入れない。フェーズ2でオプション(オン/オフ)として検討する

### ③ AIによるカット判定(`vision.classify_segments`)

- 各区間から3コマ(始め・中・終わり)を取り、6区間ずつまとめて Claude に送る。応答は JSON スキーマ指定(structured outputs)で受け取る
- モデルは既定 `claude-opus-5-5`(環境変数 `AUTOEDIT_MODEL` で変更)。安全判定で断られたときはサーバー側で別モデルに回す設定(fallbacks)を付ける。Bedrock 等で使うときは `AUTOEDIT_NO_FALLBACK=1`
- 1まとまりの判定が失敗しても全体は止めず、そのまとまりだけファイル名での判定に切り替える
- 1区間ごとに次を返させる
  - `room`: 部屋の種類(外観、エントランス、玄関、廊下、リビング、ダイニング、キッチン、寝室、洋室、和室、収納、洗面、浴室、トイレ、バルコニー、眺望、その他)
  - `beauty`: 映え度(0〜10)
  - `is_transit`: 移動中など見せ場でないか
  - `window_only`: 窓辺に寄って窓・ブラインド・窓越しの景色だけを写した画角か(部屋の広がりが分からない。映えないので使わない。手動ラベルでも `window_only: true`)
  - `note`: 短い内容メモ
- APIキーがないときは、ファイル名のキーワード(例: `living_01.mp4`)か手動ラベル `labels.yaml` で判定する(最低限モード)

### ④ 構成の組み立て(`planner.py`、テンプレートは `config/template.yaml`)

| パート | 尺 | カットの選び方 | テロップ |
|---|---|---|---|
| 見所 | 3.2秒 | 外観 → 眺望 → リビング → バルコニーの順に探し、なければ映え度最大。水回りは使わない | hook |
| キャッチ | 6.4秒(2カット) | エントランス・共用部 → 外観 → 玄関 → 眺望 → リビング。2カットは別の場所から。主役の部屋(リビング)はほかに候補があれば使わない | catch(2カットにまたがる) |
| 広告 | 2.5秒 | 静止画。動かさない(寄ると文字が読みにくい) | ― |
| 共用部 | 1カット3.2〜4.4秒、最大5カット | マンションの外観 → 緑 → エントランス・ロビー → エレベーターホール。見どころ(タワー・ロビー等、near が外観・エントランス)はその場所の先頭。冒頭で使ったクリップの続きより別のクリップを優先。素材が無ければ省く | 各カットに room(Exterior / Entrance / Lobby など) |
| ルームツアー開始 | 2.8秒 | 廊下 → 玄関(廊下を進みながら START) | start |
| 部屋紹介 | 1カット3.6〜5.2秒(映え度が高いほど長い)、リビング・洋室は2カットまで、他は1カット、最大9カット | リビング → ダイニング → キッチン → 寝室 → 洋室 → 和室 → 収納 → 洗面 → 浴室 → トイレ | 各部屋の1カット目に room |
| 映え + CTA | 5.0秒 | バルコニー → 眺望 → リビングで一番映えるカット | cta + 矢印 |

- **物件ならではの見どころ(highlights)を必ず伝える**: 基本の部屋だけでなく、サウナ・屋外テラス・大理石の天板・ガレージ・土間収納・パントリーなど、その物件の特徴を物件資料から優先度順に挙げ(`property.yaml` の highlights、AIが自動で作る)、映像の中から探して専用のテロップ(Sauna / Terrace / Pantry など。`copy.yaml` の features)で見せる
    - 賃貸ではなかなかない特徴(rare: サウナ、テラス、ルーフバルコニー、専用庭、大理石、ガレージ、吹き抜け、アイランドキッチン、眺望)は、尺が長くなっても落とさない
    - よくある特徴(土間収納・パントリー・WIC・ランドリー)は、洗面などの基本の部屋より後、廊下のつなぎより先に落とす
    - 冒頭テロップ・キャッチ・サムネで言っている見どころが映像に無いときは警告する
- **主要な生活空間は必ず魅力的に見せる**: LDK・キッチン(`core_rooms`)は必ず部屋紹介に入れ、落とさない。その一番映えるカット(と同じ構図のカット)は部屋紹介のために取っておき、冒頭には使わせない。同じ部屋の2カット目は、1カット目とほぼ同じくらい映えるとき(映え度の差1以内)だけ使う(初回、冒頭がLDK・キッチンのベストを使ってしまい、部屋紹介に魅力のないLDKの映像が残った反省)
- **冒頭で引きを強くする**: 見所(最初のカット)は冒頭テロップが言っている見どころの映像(例: ガレージなら外観)。キャッチの2カットは、残りの中で物件で一番映えるカット(映え度 + 見どころのボーナス)を別の場所から選ぶ
- 尺が上限を少し超えるだけなら、部屋や見どころを丸ごと落とさず、各カットを少しずつ短くして収める
- **歩いて回る順に並べる**: 家の中を歩いた長回しがあれば、部屋紹介はその中に出てくる順(1F→2F→3F)に並べる(`tour_order: walk`)
- **場面が大きく変わるところに廊下をはさむ**: 区画(玄関まわり・LDK・個室・水回り)が変わるところに、その間を歩いた廊下・階段のカットのうち、ゆっくり落ち着いたものを3.2秒はさむ(1本に2回まで)。部屋 → 廊下はディゾルブ、廊下 → 次の部屋は歩きの流れのままカット
- 同じ部屋の中では撮影順に並べ、カメラの動きの流れを自然にする
- **ゆったり見せる方針**: カット数を減らして1カットを長く見せる。部屋紹介が9カット(見どころ込み、廊下のつなぎは除く)を超えるか合計が70秒を超えたら、トイレ → 収納 → 同じ部屋の2カット目(映え度の低い方) → 和室 → ダイニング → 洗面 → よくある見どころ(優先度の低い順) → 廊下のつなぎ → 洋室 の順に落とし、最後に各カットを均等に短くする。珍しい見どころは落とさない。30秒に足りないときは警告を出す
- 全素材を0.8倍速にしてゆっくり見せる。60fps素材はそのまま、30fps素材は前後のコマを混ぜて60fpsの中間コマを作ってから(`motion.low_fps_interp: blend`)。動きを推定する高画質な方法(`flow`)もあるが約30倍遅い
- カメラが速く動いているカットほど、さらにスローにする(見かけの速さを 0.12画面幅/秒 に近づける。下限は 60fps素材 0.5倍、30fps素材 0.7倍)
- 同じ映像を2回使わない: 各カットの中央のコマの特徴点を比べ、同じ場所を同じ向きから撮ったカット(対応の取れる点が25以上。実測で同じ映像は48〜119、別の映像は0〜16)は、別ファイルでも1回だけ使う
- **窓辺だけの画角は使わない**: 窓・ブラインドに寄って外を写しただけのカット(部屋の広がりが分からない)は、映え度が高く判定されても使わない(グランフロントの確認で、LDKの窓辺のカットが「いらない」と指摘された反省)。眺望はバルコニーや、景色を主役に広く撮ったカットで見せる
- **トイレは部屋が少ないときだけ**: 映えにくいので、部屋紹介の部屋数が `min_rooms` に足りないときだけ入れる(`only_if_few`)
- **マンションは共用部も見せる**: 外観・緑・エントランス・ロビーなど建物の魅力は、広告のあと・部屋に入る前の「共用部」パートでまとめて見せ、共用部 → ルームツアーSTART はやわらかく切り替える(章の切れ目)
- 使うカットは、部屋ラベルの範囲の内側だけに縮める(範囲からはみ出した部分には廊下など別の場所が映っているため)

### ⑤ 書き出し(`render.py`)

- フレーム単位で合成し、ffmpeg で H.264 に書き出す
- BGM は `共通/BGM/` から選び、動画より短ければループさせ、動画の尺で切って最後の1.5秒でフェードアウトする
- 素材は縦撮り(9:16)が前提。キャンバスいっぱいに拡大して使う
- 横長素材が混ざった場合は、予備として中央を縦に切り出す(画質が大きく落ちるので、撮り直しを優先する)
- 全カットで1.00→1.04倍にゆっくり寄る(サブピクセル補間でガタつかない)
- **カット確認シート** `出力/物件名_カット確認.jpg`: 使った各カットの始め・中・終わりのコマと、付けた部屋名・テロップを並べた画像。部屋名テロップと映像が合っているか(廊下のカットに「Powder room」が付いていないか等)を投稿前に一目で確認する

## 5. トランジション仕様

**基本はカット(動きつなぎ)**。毎回トランジションを入れると映像がうるさくなるので、意味のある切れ目だけやわらかく切り替え、「章が変わった」と伝わるようにする。参考動画もほぼカットで、前後のカットの動く向きと速さがそろっているから滑らかに見えている。

| つなぎ目 | 種類 | 長さ | 理由 |
|---|---|---|---|
| 基本(同じ区画の中、見所・キャッチの中) | カット | 0秒 | 前後で動く向きがそろっていれば、カットが一番すっきりして高級感が出る |
| 前後で動く向きが逆(左パン→右パン等) | ディゾルブ | 0.6秒 | カットだとガクッとするので、短くなじませる |
| 区画が変わる(LDK→個室→水回り。`template.yaml` の zones) | ぼかしディゾルブ | 1.0秒 | 「次のエリアへ」を伝える章の切れ目 |
| START → 最初の部屋 | ぼかしディゾルブ | 1.0秒 | ルームツアーの始まり |
| 最後の見せ場(眺望・バルコニー)へ | ライトリーク | 1.2秒 | 光が差し込んで開ける演出。1本に1回だけ |
| 広告の前後 | ディゾルブ | 0.5秒 | 広告画像を落ち着いて見せる |
| 最後 | 黒フェード(TikTokのループ再生を考えて初期値は無し) | 0〜0.6秒 | |

- やわらかい切り替えは、広告の前後を除いて1本に5回前後まで
- どのトランジションも、前後どちらかのカット尺の40%を超えない
- 素早いパン、スライド、スピンなどの派手なトランジションは使わない
- 使える種類: カット / ディゾルブ / ぼかしディゾルブ / ライトリーク / ズームスルー / ソフトワイプ / ディップ。`style.yaml` の `transitions` で場面ごとに選ぶ
- 見比べ用の動画: `python -m autoedit.transition_samples 物件動画/物件名` → `出力/トランジション比較.mp4`

## 7. 撮影ガイド(外部の撮影者に共有する)

撮影は外部の撮影者に依頼する。全自動の品質は素材でほぼ決まるので、依頼時に次を必ず伝える。詳しい版(数値つきの理由、部屋ごとの撮り方、チェックリスト)は共有用ドキュメント「ルームツアー撮影ガイド」にまとめた。

- 初回素材(アルモニー千里)の実測: カメラの速さ 0.16〜0.30画面幅/秒(理想 0.08〜0.12)、1カット3.6〜5.1秒(理想 10〜12秒)、30fps。編集でスローにしても落ち着いて見えなかった主な原因は撮り方
- 1カットは「2秒止め → 6〜8秒ゆっくり動かす → 2秒止め」。狭い洗面・浴室・トイレは左右に振らず、ほぼ止めて撮る
- レンズは基本1x(0.5xは端が歪み、動きが速く見える)
- 物件資料に書かれた特徴(ガレージ、サウナ、テラス、大理石の天板など)は必ず撮る。初回の素材ではガレージの中が撮られておらず、見せられなかった
- 部屋と部屋の間の廊下・階段も、ゆっくり進むカットを1本ずつ撮る(場面の切り替えのつなぎに使う)

- スマホ・カメラとも**縦向き**で撮る(9:16。横で撮ると中央を切り出すことになり、画質も構図も落ちる)
- **60fps** で撮る(自動で0.8倍スローにして、さらにゆっくり見せられる。30fpsだとスローにできない)
- **部屋ごとにクリップを分ける**(1部屋 = 1〜2本。部屋から部屋への移動中は録画を止める)
- ファイル名に部屋名を入れてもらえると、AIが使えないときの判定に使える(例: `living_01.mp4`、`リビング1.mov`)
- ジンバルを使い、各部屋で「ゆっくり一定速度の動き」を5〜10秒撮る(前進、横移動、ゆっくりパンのどれか)
- 見所用に、外観のあおり、エントランス、バルコニーからの眺望を必ず撮る
- 照明は全部つける
- 納品は LINE の「ファイル」送信で、動画と物件詳細資料(間取り図入りの PDF・画像)を一緒に送る

## 10. サムネイルと投稿文(「不動産テンプレ」)

これまで ChatGPT で作っていたサムネとキャプションを、動画と同時に作る。

### 10-1. 物件番号

- 表記は必ず `No.L###`(例: No.L036)。`property.yaml` の `number`、または `--number L036` で指定する
- 指定が無ければ `共通/物件番号.txt`(最後に使った番号)の次の番号。使った番号は自動で記録する

### 10-2. サムネイル(`thumbnail.py`、設定は `style.yaml` の `thumbnail`)

- 完成見本(No.L030〜L032)の黒×ゴールドのデザインをマスターとして固定する。比率 1149×1369 は変えない
- 固定: 黒背景、ゴールドの外枠、最上部の光るライン、タイトル、サブタイトル、3分割の情報バー、角丸+ゴールド枠の物件写真、中央の白い再生ボタン、最下部の物件番号と左右のゴールド線
- 差し替えるのは、タイトル(《》で囲んだ部分がゴールド。ゴールド内の数字は大きく、白のかなは少し小さく)、サブタイトル、情報バー3項目、物件写真、物件番号だけ
- 物件写真は、物件フォルダの「サムネ」を名前に含む画像。無ければ動画の外観(無ければ見所)カットから切り出す
- 物件名は入れない

### 10-3. 投稿文(`post.py`)

- 動画冒頭テロップ = hook、投稿タイトル = `post_title`
- キャプション: 1行目に物件番号、2行目に【見出し】、本文、最後に「気になる方はDMで【L###】と送ってください。」
- ハッシュタグ・家賃・独立した物件情報一覧は出さない。安っぽい煽り(神物件、ヤバすぎる など)は使わない
- 文言は⓪の物件資料の読み取りで一緒に作る(サムネのタイトル・サブ・情報バー、投稿タイトル、見出し、本文)。資料に無い情報は書かない

### 10-4. 納品前チェック(自動)

キャプション1行目が物件番号か、CTAの番号が一致するか、ハッシュタグ・家賃らしき表記が無いか、サムネに物件名が無いか、情報バーが3項目か。見つかった点は `_投稿.txt` の最後とログに出す。サムネの比率・レイアウトはテンプレートで固定されている。駅名・徒歩分数・面積などの事実は、担当者が募集図面と照らして確認する。

- 安定区間の自動抽出(移動・手ブレ・ピンボケの除外)。ffmpeg 経由の読み込みで、回転メタデータと日本語パスに対応

- APIキーなしの最低限モード(ファイル名 / 手動ラベル)
- 構成テンプレートへの自動割り当てと、30〜70秒への尺合わせ
- ディゾルブ、ぼかしディゾルブ、白フェード、ゆっくり寄り、60fps素材のスロー、BGM のループとフェードアウト
- 5種類のテロップ(傍点、流れる START、ふわっと出る部屋名、CTA ボックス、アイコンを指す矢印)
- 矢印確認用のプレビュー(`python -m autoedit.preview`)
- テスト(`python -m pytest tests`。Claude API は応答を差し替えて検証し、実APIは呼ばない)

### 本番運用の前にやること

1. 撮影者に 60fps での撮影を依頼する(初回の実素材は 30fps だったため、0.8倍スローが効いていない)
2. 実際の撮影素材(1物件分、縦・60fps・部屋ごと)でしきい値(`max_speed` など)を調整する。今までのテストは、YouTube の参考動画を切り分けた編集済み・360p の素材と、合成したテスト映像しかない
3. `ANTHROPIC_API_KEY` を設定して、物件資料の読み取り・部屋判定を実資料・実素材で検証し、プロンプトを調整する(実APIでの実行は未実施)
4. 実際に使っている書体ファイルを `共通/フォント/` に置き、現状動画と並べて位置とサイズを微調整する
5. テスト投稿で、矢印がアカウントアイコンを指しているか確認し、`arrow.target` を確定する
